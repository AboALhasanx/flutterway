## 0. Design Read (قبل أي قرار)

**Reading this as:** تطبيق Windows تعليمي/إعدادي للطلاب المبتدئين، بهوية "ثقة هادئة" وليس "منتج تسويقي"، يميل إلى **رحلة موجّهة (Guided Path)** وليس Dashboard، مع تباين منخفض، حركة قليلة، وكثافة متوسطة.

| Dial | القيمة | السبب |
|---|---:|---|
| `DESIGN_VARIANCE` | **3/10** | جمهور مبتدئ + ثقة + إتاحة؛ لا asymmetry درامي |
| `MOTION_INTENSITY` | **2/10** | الحركة فقط لتوضيح الحالة/الانتقال |
| `VISUAL_DENSITY` | **4/10** | تطبيق يومي، ليس cockpit ولا معرض فني |

**الجملة الحاكمة:**
> الطالب لا يريد "أدوات"، يريد **أن يرى تطبيقه على هاتفه**. كل شاشة يجب أن تجيب: "ما الخطوة التالية؟"

## 1. الفكرة والجمهور

- **الجمهور:** طالب جامعي/مبتدئ، أول مرة يثبّت Flutter، إنترنت متذبذب، لا يعرف Gradle/ADB/SDK/NDK.
- **المهمة الأساسية:** من "ما عندي بيئة" إلى "تطبيقي يعمل على هاتفي" بأقل قرارات.
- **المهمة الثانوية:** تعديل سريع (Hot Reload) ثم فتح VS Code.
- **ما ليس مهمة التطبيق:** عرض كل الفحوصات، كل أدوات الإنقاذ، وكل تفاصيل الجهاز في نفس الشاشة.

**المبدأ:** التطبيق **مرشد**، وليس IDE ولا لوحة تحكم.

## 3. قواعد UX/UI المستنتجة

1. **رحلة واحدة، ليست لوحة تحكم.** الشاشة الافتراضية = الخطوة التالية.
2. **إجراء أساسي واحد لكل شاشة.** زر واحد فقط بلون primary.
3. **توصية بدل اختيار.** USB هو المسار؛ المحاكي داخل "خيارات متقدمة".
4. **لغة الطالب.** لا Gradle/ADB/ABI على السطح؛ التفاصيل داخل "عرض التفاصيل".
5. **تقدّم حقيقي.** "الخطوة 2 من 4" + أحداث فعلية، لا ticker وهمي.
6. **نتيجة بصرية فورية.** معاينة الهاتف، احتفال بعد أول تشغيل، فرق واضح بعد Hot Reload.
7. **خطأ قابل للعلاج.** جملة بسيطة + إصلاح واحد + "لماذا؟".
8. **Progressive disclosure.** 3 عناصر كحد أقصى؛ الباقي مطوي.
9. **محتوى قصير.** بطاقة = عنوان + سطر واحد.
10. **ثقة.** لا أرقام مزيفة. أي رقم إما مقاس أو موسوم "تقديري".
11. **اتساق.** Tokens للخط/المسافة/اللون/الحدود/الحركة.
12. **إتاحة.** 14px، تباين 4.5:1، focus، keyboard، aria، RTL/bidi.
13. **تجاوب.** 980×740، 860×640، DPI 125–150%، بلا horizontal scroll.
14. **الأدوات في سياقها.** Rescue عند الخطأ، Device كشريحة، Dev مخفي.
15. **تعلّم بالممارسة.** Hot Reload يبدأ بمهمة صغيرة، ثم محرر كامل.
16. **حذف قبل إضافة.** إذا كان العنصر لا يضيف معنى/حالة/إجراء، احذفه.

## 4. Information Architecture المقترحة

```
Header: [FlutterWay]   [الرئيسية] [مشروعي] [تعلّم] [المزيد]   [الثيم]
```

### الرئيسية (Next Step)
- **بدون بيئة:** بطاقة واحدة: "شغّل أول تطبيق على هاتفك" + 4 خطوات + CTA.
- **بيئة جاهزة:** "مشروعك جاهز" + 3 إجراءات:
  1. افتح VS Code
  2. جرّب Hot Reload
  3. تعلّم
- شريحة صغيرة: "الهاتف متصل" (بدون تفاصيل).
- لا Doctor/Rescue/Device في الرئيسية.

### المعالج (4 خطوات)
- **خطوة 1:** "هاتفك هو الأسرع" + زر "متابعة". لا USB/محاكي.
- **خطوة 2:** 4 مراحل + progress حقيقي + "عرض التفاصيل".
- **خطوة 3:** كشف الهاتف + إرشاد بسيط.
- **خطوة 4:** VS Code + Hot Reload + "ابدأ".

### مشروعي
- بطاقة "المشروع النشط" + زر "مشروع جديد" + قائمة حديثة (ثانوية).
- 3 أزرار كحد أقصى: ابنِ/شغّل، افتح VS Code، Hot Reload.
- "تنظيف البناء" داخل قائمة `...`.

### تعلّم
- 3 بطاقات فقط: Hot Reload، Stateless/Stateful، أخطاء شائعة.
- "المزيد" يفتح المفكرة الكاملة.

### المزيد
- Doctor، Projects، Rescue، Device، Cheatsheet، Dev (مخفي).
- Rescue يظهر تلقائياً عند فشل البناء/الاتصال، مع "حل المشكلة".

### شاشة البناء
- Timeline 5 مراحل: تجهيز → بناء → تصغير → تثبيت → فتح.
- سطر حالة واحد + نسبة/زمن.
- "عرض سجل Gradle" مطوي.
- بعد النجاح: "شاهد تطبيقك" + "جرّب Hot Reload".

### Hot Reload
- **وضع المبتدئ:** "غيّر هذا النص" + معاينة هاتف + زر "جرّب الآن".
- **وضع متقدم:** المحرر الكامل + السجل.
- لا تبدأ بمحرر 340px وسجل VM Service.

## 5. نظام التصميم (Design Tokens)

### Typography
- الخط: Cairo.
- الأحجام: `12 caption / 14 body / 16 section / 20 card title / 28 hero`.
- الأوزان: 400/600/700/800.
- line-height: 1.6 للنص، 1.3 للعناوين.
- **ممنوع 10px** في أي نص أساسي.

### Spacing
- 4 / 8 / 12 / 16 / 24 / 32 / 48.
- بطاقة: padding 20.
- فجوة بين البطاقات: 12-16.
- عرض المحتوى: 860-960 كحد أقصى.

### Colors (الأدوار)
- `bg` داكن `#0b0f19` / فاتح `#f8fafc`.
- `surface` `#121a2b` / `#ffffff`.
- `primary` `#54c5f8` (فاتح `#0284c7`).
- `success` `#10b981`، `warning` `#f59e0b`، `danger` `#ef4444`.
- `text` `#f3f4f6` / `#0f172a`، `muted` `#94a3b8` / `#64748b`.
- **قاعدة:** لون accent واحد. لا gradients/glows زخرفية.

### Radius & Borders
- Radius: 10 for small, 16 for cards, 999 للـ status chips فقط.
- Borders: 1px `--card-border`؛ لا ظلال إلا للمودالات/القوائم.

### Buttons
- Primary: واحد لكل شاشة.
- Secondary: outline.
- Ghost: للثانوي.
- Danger: للحذف/الإيقاف.
- Height: 42-44؛ نص لا يلتف.

### Cards & Badges
- البطاقة فقط لمحتوى متكرر أو وحدة قابلة للنقر.
- لا nested cards.
- شارة واحدة كحد أقصى، وليست كل بطاقة خضراء.
- الأيقونات: عائلة واحدة، stroke 2، أحجام 14/16/20.

### Motion
- 150-220ms، لتوضيح الحالة فقط.
- احترام `prefers-reduced-motion`.
- لا ticker وهمي ولا نبضات لا نهائية.

## 6. الحالات المطلوبة (States)

| الحالة | المطلوب |
|---|---|
| Loading | Skeleton/نص واضح، لا شاشة فاضية |
| Empty | رسم/أيقونة + جملة + CTA |
| Error | سبب بسيط + إصلاح واحد + "لماذا؟" |
| Success | ماذا حدث + الخطوة التالية |
| Offline | رسالة صريحة + إعادة محاولة |
| No device | إرشاد USB + زر فحص |
| Build failed | فشل واضح + سجل مطوي + إصلاح |
| Hot Reload error | الخطأ + آخر نسخة ناجحة |
| Unauthorized device | سماح على الهاتف + إعادة فحص |

## 7. Responsive & Accessibility

- `@media (max-width: 920px)`: الشبكات عمود واحد، subnav 3 عناصر + More.
- `@media (max-width: 760px)`: الهيدر يلتف، الأزرار full-width.
- 980×740، 860×640، DPI 125%، 150%: لا قص/تراكب/scroll أفقي.
- 14px body minimum، contrast ≥ 4.5:1.
- focus-visible واضح، tab order منطقي، Escape للمودال.
- aria-label للعناصر الأيقونية، `role="dialog"`، `aria-live` للسجل/الحالة.
- `user-select: text` للسجلات والأكواد.
- لا تعتمد على hover فقط.

## 8. خطة التنفيذ (مراحل)

### Phase 0 — Design contract (قبل الكود)
- اعتماد هذه الوثيقة.
- تعريف Tokens في CSS variables.
- تحديد "شاشة واحدة = إجراء واحد".
- **الملفات:** `gui/onboarding/index.html` (CSS variables)، وثيقة الخطة.

### Phase 1 — IA + الرئيسية
- استبدال 6 تبويبات بـ 3 + More.
- بناء "الرئيسية" كـ Next Step.
- إخفاء Dev Reset خارج `--dev`.
- نقل Doctor/Rescue/Device إلى More.
- **قبول:** لا أكثر من 3 أزرار تنقل، CTA واحد.

### Phase 2 — Wizard + Build
- حذف اختيار USB/المحاكي من الخطوة 1.
- Progress حقيقي + "عرض التفاصيل".
- Build Timeline 5 مراحل + سجل مطوي.
- نصوص قصيرة.
- **قبول:** طالب يفهم "ماذا يحدث الآن" دون قراءة Gradle.

### Phase 3 — Doctor + Projects + Hot Reload
- Doctor: ملخص + المشاكل فقط.
- Projects: بطاقة نشطة + إنشاء + حديث.
- Hot Reload: "غيّر هذا النص" + معاينة + وضع متقدم.
- Rescue: سياقي عند الخطأ.
- **قبول:** المبتدئ يجرّب Hot Reload دون فتح محرر كود كامل.

### Phase 4 — Visual system
- Typography/Spacing/Buttons/Cards/Badges.
- حذف الشارات/الفقرات/التكرار.
- استبدال الأرقام المزيفة بقياسات أو وسم "تقديري".
- **قبول:** لا 10px، لا شارة على كل بطاقة، لا primary مزدوج.

### Phase 5 — States + Responsive + A11y
- Loading/Empty/Error/Success.
- `@media` + DPI + focus + aria.
- **قبول:** لا scroll أفقي، axe critical = 0، keyboard كامل.

### Phase 6 — User testing
- 5 طلاب مبتدئين، Think Aloud.
- قياس: زمن أول تطبيق، عدد مرات الحيرة، الأخطاء، SUS/SEQ.
- **قبول:** 4/5 يصلون لتطبيق على الهاتف دون مساعدة.
